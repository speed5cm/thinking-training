# “重新规划”隔离验收

本次只改动实验 Sigma Adapter，增加家长发起重规划的流程；继续使用现有会话存储、规划存储和校验器。没有切换儿童正式入口。所有学习者、回答和家长确认均为测试者虚构；结果不代表真实儿童学习效果。

## 真实 Codex Agent 场景

在 `/tmp` 白名单副本中，以现有示例计划及一条虚构 C01 问答初始化 v1；不复制真实学习记录、仓库凭据或历史审计数据。测试者保存 v1 的完整课程输入快照，再修改副本 Wiki。两轮之间用同一 Codex 线程模拟家长确认；发布前后均检查规划历史。实验副本中 18 个题卡及审核文件与项目一致。

| 场景 | 实测结果和证据 |
| --- | --- |
| 已审核范围内的 Wiki 变化 | C01 教学动作补充区分直接描述、原因猜测和待核实信息，见 [差异](safe-wiki.diff)。Agent 核对旧快照完整摘要与 v1 一致，比较试点材料及学习记录，保留路线骨架，提出近期第 1、3、7 天短复习，保存候选摘要、版本和输入，并等待确认。见 [提案日志](safe-proposal.jsonl)。 |
| 模拟家长确认并发布 | 测试者明确确认上述候选。Agent 重新核对摘要、版本和输入，调用校验器和发布接口，成功发布 v2；v1 保留。见 [确认日志](safe-confirm.jsonl)、[候选](safe-candidate.json)、[历史](safe-plan-history.json)和[会话](safe-session.json)。路线中的复习建议不是已排期任务。 |
| Wiki 未变且无需调整 | 在前一个同类安全变化实验中，发布 v2 后再次要求重规划，Agent 核对后保留 v2，未重复发布。见 [日志](unchanged.jsonl)。该轮使用的是补充候选摘要绑定前的 Adapter；无变更分支未受该补充影响。 |
| 材料覆盖不明确 | C01 增加“两种不同且可核实的解释”，见 [差异](conflict-wiki.diff)。Agent 核对旧快照及试点材料后指出覆盖不明确，暂停受影响教学、复习与发布，要求课程负责人核对；v1 保持过期，未发布 v2。见 [日志](conflict.jsonl)和[历史](conflict-plan-history.json)。 |

## 回归与限制

- `python3 -m unittest discover -s tests -v`：33 项通过。
- `python3 -m unittest discover -s pilot-c01-c02/tests -v`：24 项通过。
- `python3 scripts/generate_roadmap.py --check`：通过，14 概念、2 个试点可用快照。
- 校验器只验证结构和输入摘要，不能审核教学语义或授予授权。家长确认、候选摘要核对和内容判断是 Agent 协议，不是发布接口强制实施的审批；候选或输入在检查和发布之间被非协作式修改的竞态未解决。
- 上述只是有限的成人模拟；未验证确认前候选被篡改、旧快照无法获得、所有类型 Wiki 变更或跨进程失败恢复。旧记录迁移、受控发布维护、真实儿童效果及正式入口切换仍未验收。
