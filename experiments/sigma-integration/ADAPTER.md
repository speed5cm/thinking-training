# 隔离验证适配：Sigma + 儿童试点

本文件优先于同副本 `.claude/skills/sigma-with-wiki/SKILL.md` 中冲突的段落；无冲突的 survey、问题循环、回顾和误区追踪沿用原版。上游原文件 Git blob `4deba6755b43a7e469b08cb2d51b9608e217bc8d`，许可证与引用文件随原件保存。本文件是验证适配，不是正式上线。

1. 成人陪同，使用化名。Sigma 会话存到 `pilot-c01-c02/records/<化名>/sigma/`；不可使用上游全局路径或旧跨话题画像。状态须在每次提出问题前、回答后、暂停/结束时持久化，保留原话、问题、提示、分析、假设、动作、原因、家长观察和路线版本；未答问题恢复原题。此验证适配不用于真实儿童。
2. 根 Wiki 没有 overview 和上游类型标记：读取 `wiki/index.md`、全部 14 页、`curriculum/12-week-plan.md`，由 `python3 scripts/generate_roadmap.py --check` 检查结构。14 页是课程范围，不等于授权进入。保留每概念 Wiki Pages；上游缺 overview 的 plain `/sigma` 回退禁止使用。每次进入或恢复概念重读根 Wiki 和试点概念、相关资料；冲突或缺失即停止。
3. 用 Sigma 的路线推理生成候选，输出到 `personal-roadmap.json` 的现有 schema 并调用 `scripts/validate_personal_roadmap.py` 校验；规划只是建议。停止调用独立 Planner Skill，保留其校验器。不能凭诊断标 mastered、跳过先修、凭 80% 或自评宣布掌握。以 `learning_evidence.py recommend`、证据聚合、家长确认和 coach 即时门禁为权威。当前只有一张 C01 已发布训练卡，不能满足不同题卡掌握证据；C02 正常情况下不可进入。
4. 使用 Sigma 的问题、回答分析、追问、提示、例子、跨情境与复习过程，AI 自审适龄、只问一个问题、符合 Wiki、不泄露正式题答案。动态练习不是正式测评或授权。正式测评题、原题提示及支持仅走 `coach.py`，完成后通过 `learning_evidence.py capture` 采集；不能把动态练习写成已审核卡。对连续不理解提供不同方式、平行示范或休息；疲劳、拒绝或挫败立即停止并保存。只在具体证据支持时记录待验证假设；未知即 unknown，禁止学习风格、心理和稳定能力标签，不强迫填误区表。
5. 不自动打开浏览器；HTML 和可视化只在需要时生成，不用上游固定每轮重写 HTML。继续学习须重新 survey、重验发布和先修，并先恢复未答问题；复习只在已允许的概念上进行。对未发布内容，未来路线可列但不得将其作为正式教学或测评题。

## 强制会话存储协议

本节覆盖上游所有直接读取或写入 session.md、画像及逐轮记录的指令。开始、继续、查看、暂停和结束时均先运行 `python3 scripts/sigma_session_store.py read --learner <化名>`；只从返回的 `state`、`session`、`turns` 和 `revision` 恢复。每次提问展示前、接收原答后及暂停或结束前，将完整的三个字段作为 JSON 经标准输入提交给 `python3 scripts/sigma_session_store.py commit --learner <化名> --expected-revision <读取到的修订号>`；`turns` 必须保留全部已提交记录并追加新记录。先提交成功，才能展示问题或声称已保存；失败即停止，冲突时重新读取并根据最新会话重新判断，不盲目覆盖。提交载荷不含 revision 和 schema_version。不要把儿童原话放入命令行参数或历史。

`session-snapshot.json` 是 Sigma 会话唯一权威来源；禁止独立创建、修改或读取旧的 `state.json`、`session.md`、`turns.jsonl` 作为会话状态。存在任何旧文件时接口停止，须人工核对和安全迁移后才能继续；不得自动删掉旧文件或当作新会话。路线、coach 事件和正式证据各有自己的存储及门禁，不包含在此快照事务中；跨系统操作中断后须重新核对，不能声称整个学习会话跨文件原子一致。直接绕过接口的文件操作不受程序强制约束，本协议尚需真实 Agent 端到端验收。

`turns` 使用追加事件：展示前追加 `{"type":"question","question_id":"会话内唯一ID","text":"问题原文"}`；收到回答后在同一次提交中依次追加 `{"type":"answer","question_id":"同一ID","text":"回答原文"}` 和 `{"type":"analysis","question_id":"同一ID","analysis":{"understanding":"具体观察","reasoning":"理由或 unknown","support":"提示依赖","next_step":"教学判断"}}`。analysis 是非空对象，保留实际的完整分析，可增加必要字段，未知写 unknown；不得仅用会被覆盖的 state 字段存储。不得修改已提交事件。追问使用新 ID。每次仅有一个未答问题；暂停、恢复时按事件顺序寻找没有对应 answer 的 question，并恢复其原文。重复 ID、孤立回答、多个未答问题或无法解释的旧记录须停止并人工核对。快照校验新增回答及分析的关联和顺序；旧记录不自动重写，其他语义仍由 Agent 检查。

`state.planning_basis` 是可选 JSON 对象，只记录影响概念顺序、长期复习需求或教学目标的实质性变化；及时更新真实理解变化，不能为了避免重规划隐瞒。每轮分析、进度显示、短期提示、选例子、下一题教学动作和暂停放在其他状态或追加事件中，不能放入 planning_basis；仅仅选择平行例子不会使路线失效。路线摘要独立绑定正式证据、家长确认及 Wiki，普通问答和修订号不触发重规划。Wiki 和正式授权每次仍须实时检查。

动态复习使用 `sigma_plan_store.py` 同一规划存储：从已保存的问答和 analysis 发现需要复习时，标准输入 `{"concept":"C01","question_id":"来源题ID","reason":"具体依据","interval_days":1}` 调用 `schedule-dynamic --learner <化名>`。`status` 的 `dynamic_reviews` 显示任务及到期状态，不因调度强制重发布路线。到期后 Sigma 自主设计动态题，question 事件额外写入 `review_task_id`；像普通问答一样原子保存 answer 和 analysis。然后标准输入 `{"task_id":"任务ID","question_id":"复习题ID","result":"correct|partial|incorrect","next_interval_days":2}` 调用 `complete-dynamic --learner <化名>`，一次原子操作完成任务并创建下一任务。默认可在正确后按 1、2、4、8、16、32 天延长，困难时缩短；由 Sigma 结合具体表现调整 1—32 天。重复提交、未到期或没有关联完整问答分析时停止并核对。任务和结果仅为动态学习记录，不是正式证据、掌握或晋级授权。会话保存与队列更新不是跨文件事务：若任一步失败，保留问答，读取两侧状态，确认任务是否完成后再继续，不声称两侧都已成功。

路线过期时先停止受影响的复习，重新读取 Wiki 和已审核材料并检查授权；安排和完成动态复习的存储操作也会拒绝过期路线。可优先使用 Git 历史或已有内容快照比较旧版；找不到可信旧内容时不能臆测差异。确认变更仍在已审核范围内后才更新路线；要求超出范围或存在冲突时暂停并请求人工确认，不发布未经确认的路线。历史任务和已保存的回答、分析须保留。结构校验与摘要匹配不能代替对教学内容及授权的判断。

## 家长指令：重新规划

家长说“重新规划”时，Sigma 负责分析和提出方案，不调用另一个 Planner。先按会话协议读取学习记录，运行 `sigma_plan_store.py status --learner <化名>` 和 `validate_personal_roadmap.py context --learner <化名>`，读取 `sigma/plan-history.json` 最后一版的 `plan`、`inputs` 及版本，重读当前 Wiki、相关试点材料和实时建议。没有既有路线时按原有建路线流程处理。不得把家长提出重新规划本身当作对方案的确认。

比较当前输入与已有路线：Wiki 未变时结合学习记录和家长要求判断，确无调整且输入仍有效就说明理由并保留版本，不发布重复路线；仅输入摘要变化也须核对影响，不能把刷新摘要当作分析。Wiki 已变时先查明具体变更及对学习目标、先修、已审核材料和既有路线的影响，优先修补受影响步骤，仅在原路线不能有效修补时重建；新路线仍保留历史和既有复习记录。优先从 Git 历史或已有快照取得旧内容，并按校验器的完整课程输入摘要核对它与原路线一致；如果无法可靠还原，则说明不确定处并停止受影响教学及发布，不能猜测变更范围。

对比后向家长说明变化、依据、保留内容、风险及仍受限的内容。改变概念顺序、学习目标或范围、先修相关安排，或因 Wiki 实质性变化调整路线，均视为重大调整，须先展示具体候选方案并等待家长明确确认；不把笼统的“重新规划”、成人陪同或旧确认当作对新方案的批准。候选必须保持原有 schema，以独立文件保存；展示前计算候选文件 SHA-256，并通过会话接口保存该摘要、候选路径、原路线版本和三项输入摘要，供跨轮核对。确认只针对展示过的候选和当时的输入。确认后重新读取会话、上下文及候选，重新计算文件摘要；若候选、路线版本或输入发生变化，重新分析并再次请求确认。再运行 `validate_personal_roadmap.py validate --learner <化名> --plan <候选文件>`，成功后调用 `sigma_plan_store.py publish --learner <化名> --plan <候选文件>`；失败时停止并回读状态，不宣称已发布。非重大调整也须经过同一校验和发布接口。此确认流程由 Sigma 执行，发布接口本身不验证家长确认或内容语义，不能把它描述为程序强制的审批门禁。

发现新要求超出已审核材料、授权边界不清或与其冲突时，保留原版本和记录，停止受影响教学、复习及新路线发布，说明需要人工核对的具体问题；家长确认路线不能替代材料审核。规划可列未来概念，但不授予教学、正式题卡使用、先修完成或掌握资格；继续训练仍须实时检查现有门禁。
