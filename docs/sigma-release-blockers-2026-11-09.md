- **待实现**：同时改造规划校验和所有实际入口的使用点门禁，解决 `formal_gate.py` 非原子边界和 Coach 直接依赖旧证据的问题；防止先修、Wiki、撤销及内容授权被绕过。概念级授权已决定以人工审核的 Wiki 概念、教学目标、知识边界及来源为基础，绑定内容版本和摘要并支持撤销；责任人及具体操作流程待确定，质量不合格的动态题不能计证据。
- **待实现**：可信家长身份和明确确认的受控通道；现有摘要、命令行记录及 Agent 自称不能认证身份。已决定每次概念晋级须确认，无须逐题确认；当前仅允许合成模拟。

## 已验证

- 实验规划存储：`prepare` 保存候选、三个输入摘要和一次性标识，返回候选全文与摘要供家长检查；`publish --confirmed-sha` 必须引用该摘要，并再次校验候选、保存的候选和实时输入。缺少准备或确认、候选篡改、输入变化均拒绝。已发布确认不能重放。过期路线不能完成复习。
- 题卡维护：`pilot-c01-c02/scripts/publication.py` 在发布锁内对已有 verified、approved 的版本复用 coach 全部审核与题卡散列门禁，原子追加 published；对现有已发布版本追加 revoked，使既有门禁拒绝教学。合成测试覆盖审核散列不符、写入失败、发布、撤销及禁止直接重发。撤销记录不可直接复活；需要恢复教学时须人工调查并重新审校、按现有版本与审核规则准备新的获批版本。写入结果不确定时先检查审核记录和现有门禁，不盲目重试。操作命令从标准输入接收 `{"actor":"人工执行人","note":"具体依据"}`；系统不验证执行人身份，须由授权成人亲自执行并核实。
- C02 自动化：隔离副本使用额外合成 C01 题卡和虚构审核、两份合格证据与模拟家长确认，执行 C02 开始、展示、作答和证据采集；变更 C01 证据后确认失效，撤销 C02 发布则阻断。合成夹具不是正式题卡、人工审核或真实家长确认。

## 当时记录的上线阻断

以下为当时的验收记录，不代表当前入口配置。现已移除旧 Tutor/Planner 指令，并将 Sigma 路由至项目入口；真实 Agent 端到端验收和其他上线阻断仍未解决。

1. 实验规划接口的摘要是确认绑定，不是身份认证；当时的 Tutor/Planner 编排仍可使用旧个人路线文件，尚未接入此确认流程。不得声称全系统已防止未经家长确认发布，需完成入口接线、明确的人机确认及端到端反绕过验收。
2. 发布维护只处理已批准版本的首次发布和已发布版本的撤销；故障后的新版本审校和恢复仍依赖人工流程，未完成完整恢复演练。不能伪造批准或更改既有题卡以消除此阻断。
3. 正式 C01 目前只有一张已发布训练卡，不满足现行不同题卡的 C01 跨机会证据门槛。额外卡片需真实人工审核发布后，真实 C02 先修才有可能满足；不得用合成卡或重复同题替代。
4. 当时 Sigma 唯一教学入口及停用重复 Tutor/Planner 编排尚未实施。真实 Codex 教学对话的正向验收不能由直接运行单元测试替代。
